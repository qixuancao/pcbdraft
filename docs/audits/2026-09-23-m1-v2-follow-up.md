# M1 v2 试跑后的定向修复 · 2026-09-23

这轮针对 2026-09-21 M1 v2 单次试跑暴露的约束写入和 U13 GND 焊盘
`starved_thermal` 做产品侧修复。旧 run、score、题目和私有答案不回写；旧试跑
仍为 timeout / overall fail，新代码不能追认旧结果通过。

## 约束写入

- flat `add_constraint` / `update_constraint` 现在在写入前校验 `routing`：
  必须有不低于板级最小值的 `width_mm`，可选 neckdown 和参考平面字段须
  有效，目标须是已存在的 net。把 clearance/via 分类字段冒充 routing 参数
  会被拒绝并给出字段反馈。
- `placement_region` 必须且只能声明受支持的 `region`，目标须是已存在的
  component。`top` 表示板的上三分之一区域，不等于器件位于 F.Cu。
- 历史 IR 的结构化加载保持原样，因此旧错误约束仍能打开并由校验器报告。
  33 个相关定向测试及 scoped Ruff 检查通过。

## 热焊盘根因和独立诊断

旧板的 U13 pad 2 是 F.Cu 上的 GND 贴片焊盘，周围是窄间距焊盘和走线。
生成器此前让所有焊盘使用热连接，KiCad 报告该焊盘要求至少两根 spokes、
实际仅一根。KiCad 10 文档提供“只对通孔焊盘用热连接”的 zone 选项：
贴片焊盘实心连接，通孔焊盘保留热连接。

只在隔离诊断副本中改变 GND zone 的 pad connection 并重新填充，未移动
器件或走线。保留项目内自定义库的同版本 DRC 对比：原设定为 1 error
`starved_thermal` + 1 warning `silk_overlap`；新设定为 0 error + 1 warning
`silk_overlap`，两者均为 0 unconnected。诊断报告 basename 分别为
`baseline/drc-with-libs.json`（SHA-256
`b37fd4adcc8d1f7ce5b17543d8cd39aa477e0b0f187e99a751d62ee1256bcd41`）和
`pth_only/drc-with-libs.json`（SHA-256
`69443a21fa97309b6a97de802d525f45d261f4aadf33939262be928a2b70cebf`），
隔离目录 basename 为 `pcbdraft-thermal-diag-a7VXRk`。

生成器现对 GND zone 使用通孔热连接、贴片实心连接；worker receipt 如实
标识 `thermal_relief_pth`，读取器仍接受旧的 `thermal_relief` 收据。
两个真实 KiCad 原生生成用例通过（48.268 秒）；它们验证当前生成流程，
不构成完整 M1 新试跑。旧 raw PCB SHA-256 保持
`1620d212ac64863c8edace4087de4c7d9111e55a71dc2922b4b88ce027`，
旧 score SHA-256 保持
`642b8300c2f17c0bbcf6dd74a544217da2aa6fd94d6e77ff17f8ded9f8203ce1`。
